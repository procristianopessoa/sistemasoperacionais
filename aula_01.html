F1O que é um sistema operacional

Um sistema operacional (SO) é a camada de software de sistema posicionada entre o hardware e os programas aplicativos. A literatura o define por três papéis complementares, não excludentes:

  • Máquina estendida (abstração): oculta a complexidade do hardware e oferece interfaces limpas e uniformes — arquivos em vez de setores de disco, processos em vez de registradores, sockets em vez de pacotes elétricos (TANENBAUM; BOS, 2014).
  • Gerenciador de recursos: arbitra CPU, memória e E/S entre programas que competem por eles, buscando eficiência e justiça na distribuição (SILBERSCHATZ; GALVIN; GAGNE, 2018).
  • Programa de controle: garante execução correta e protege o sistema contra erros e usos indevidos, impondo limites entre processos e entre usuário e kernel (STALLINGS, 2018).

Conceito O SO transforma recursos físicos em abstrações utilizáveis e arbitra o uso desses recursos entre programas concorrentes. Suas metas clássicas são conveniência para o usuário, eficiência no uso do hardware e capacidade de evoluir sem interromper o serviço.

A porção do SO que executa em modo privilegiado e permanece residente em memória é o kernel; tudo o mais — shells, utilitários, bibliotecas — opera em modo usuário, solicitando serviços a ele.

F2Tipos de sistemas operacionais

A classificação não é por "marca", e sim pelo padrão de uso e pelas garantias que o sistema oferece:

TipoCaracterística centralExemplos
Lote (batch)Executa jobs em sequência, sem interação; origem nos mainframes dos anos 1960; sobrevive em filas e janelas de processamento noturno.Scripts batch, filas de jobs
Multiprogramável / multitarefaVários processos residentes em memória com comutação de CPU; na variante de tempo compartilhado, garante interatividade.Linux, Windows, macOS

Conceito O mesmo kernel pode servir a vários tipos: um Linux de servidor e um Linux embarcado diferem na configuração dos gerenciadores, não na essência da arquitetura.

F3Estrutura de um sistema operacional

Estrutura é a decisão de onde cada serviço vive — dentro ou fora do kernel — e define isolamento, desempenho e capacidade de evolução:

  • Monolítica: todos os serviços (processos, memória, arquivos, E/S) em um único programa privilegiado. Alto desempenho, baixo isolamento; Unix tradicional.
  • Em camadas: o SO é dividido em níveis hierárquicos; cada camada usa apenas serviços da inferior (sistema THE, de Dijkstra). Facilita depuração; impõe fronteiras nem sempre naturais.
  • Microkernel: o kernel mantém o mínimo (IPC, memória e processos básicos); demais serviços rodam como servidores em modo usuário. Máxima modularidade e isolamento, ao custo de mensagens; Mach, Minix 3, QNX.
  • Híbrida: base microkernel com serviços integrados ao kernel por desempenho; XNU (macOS), Windows NT.
  • Modular (módulos carregáveis): monolítica moderna em que drivers e subsistemas entram e saem do kernel em tempo de execução; Linux, Solaris — o modelo dominante hoje.

Conceito Toda estrutura é um compromisso (trade-off) arquitetural: quanto mais isolamento, mais comunicação; quanto mais integração, mais desempenho e mais risco. A chamada de sistema é a fronteira oficial que qualquer estrutura precisa respeitar.

Conceito Nenhum elemento age sozinho: o gerenciador de processos depende do de memória, que depende do de arquivos (swap), que depende dos drivers. O SO é um sistema de dependências cuidadosamente ordenadas.

F5SO, hardware e software: diferenças, interação e integração

ElementoNaturezaModo de execuçãoPapel
HardwareComponentes físicos (CPU, memória, dispositivos) —Fornece capacidade bruta, sem propósito próprio
Sistema operacionalSoftware de sistema Modo kernel (privilegiado)Gerencia o hardware e serve os aplicativos
Software aplicativoProgramas de usuário Modo usuário (restrito)Resolve o problema do usuário

Interação em dois sentidos. No sentido descendente, o aplicativo chama uma biblioteca (libc), que efetua uma chamada de sistema; ocorre a troca de modo, o kernel atende o pedido acionando drivers e hardware. No sentido ascendente, o hardware sinaliza eventos por interrupções; o kernel trata o evento e acorda o processo que esperava por ele.

WSL · ubuntu-lab · fronteira aplicativo ↔ kernel
aluno@wsl:~$ strace ls 2>&1 | head -4
openat(AT_FDCWD, "/etc/ld.so.cache", O_RDONLY) = 3
read(3, "\177ELF\2\1\1\3...", 832)          = 832
openat(AT_FDCWD, ".", O_RDONLY|O_DIRECTORY) = 3
LEITURA: cada linha é uma chamada de sistema — a fronteira formal
entre o software aplicativo e o kernel, capturada ao vivo.

Integração por três mecanismos. (1) Abstração: o disco vira arquivo, a CPU vira processo, a placa de rede vira socket — o aplicativo nunca toca o hardware diretamente. (2) Padronização: interfaces como POSIX e APIs de drivers permitem que o mesmo software rode sobre hardwares diferentes. (3) Virtualização: o próprio SO vira recurso gerenciado para outros sistemas — hipervisores e contêineres fecham o ciclo.

Conceito Hardware fornece, o SO arbitra e abstrai, o software consome. A integração acontece em interfaces bem definidas: chamadas de sistema, drivers e interrupções — contratos que permitem trocar qualquer uma das três partes sem romper as demais.

01Sistemas operacionais estão em toda parte

Servidores, smartphones, roteadores, TVs, automóveis, sensores e equipamentos industriais executam software e precisam controlar CPU, memória, dispositivos, armazenamento e comunicação.

Conceito O SO transforma recursos físicos em abstrações utilizáveis, como processos, arquivos, memória virtual e sockets.

04Kernel: o núcleo privilegiado

Agenda processos, protege memória, opera dispositivos, organiza sistemas de arquivos e oferece rede. Executa em modo privilegiado porque um erro nessa camada pode comprometer o host inteiro.

WSL · ubuntu-lab
aluno@wsl:~$ uname -a
Linux ubuntu-lab 6.8.0-101-generic x86_64 GNU/Linux
LEITURA: o kernel em execução é o 6.8 — a camada privilegiada se apresenta.

05Shell: interpretação e automação

O shell é um programa em espaço de usuário. Interpreta comandos, inicia processos, controla variáveis e permite criar scripts repetíveis.

WSL · ubuntu-lab
aluno@wsl:~$ echo "$SHELL"
/bin/bash
aluno@wsl:~$ whoami
aluno
LEITURA: identidade e interpretador vêm do sistema — não da janela.

Atenção Shell não é kernel: ele solicita serviços ao sistema operacional.

06Terminal: a interface textual

Terminal pode ser console físico, emulador ou sessão SSH. É adequado a servidores, contêineres, rede e recuperação porque reduz dependências e favorece automação.

WSL · ubuntu-lab
aluno@wsl:~$ tty
/dev/pts/0
aluno@wsl:~$ echo $TERM
xterm-256color
LEITURA: o terminal se apresenta como arquivo de dispositivo — no Linux, tudo é arquivo.

07Comandos como evidências do sistema

Não memorize sintaxe isolada. Identifique qual abstração cada comando torna visível. Use os botões para levar o comando ao seu WSL:

WSL · ubuntu-lab · diagnóstico inicial
aluno@wsl:~$ free -h
LEITURA: memória e swap são abstrações gerenciadas pelo kernel.
aluno@wsl:~$ df -h
LEITURA: sistemas de arquivos montados — o kernel organiza o disco.
aluno@wsl:~$ ps aux --sort=-%mem | head
LEITURA: cada linha é um processo — a abstração central do SO.
aluno@wsl:~$ ip a
LEITURA: interfaces de rede expostas pelo kernel como dispositivos.
aluno@wsl:~$ systemctl --type=service
LEITURA: daemons trabalham em segundo plano por você.

∎Síntese

O kernel administra recursos, o shell interpreta a intenção e o terminal permite interação. Hardware fornece, o SO arbitra e abstrai, o software consome. Essa base sustenta serviços Web e dispositivos conectados.
